# PulsAura CRM в Cloudflare без R2

CRM работает в Cloudflare Workers Free. Для базы и файлов используются два постоянных SQLite-backed Durable Objects: `CrmDatabase` хранит данные CRM, `CrmFiles` — изображения и резервные копии. R2, отдельная подписка на файловое хранилище и привязка карты для этого проекта не нужны. Скрипт деплоя не подключает платные сервисы и не меняет тариф аккаунта.

Интерфейс, задачи/подзадачи, клиенты, воронки, личные пространства, роли, встречи, импорт, Telegram и напоминания сохранены. На Workers Free действуют квоты Cloudflare: превышение квоты ограничивает операции, тариф автоматически не повышается.

## Быстрый деплой

Понадобятся Node.js 24 и аккаунт Cloudflare с тарифом **Workers Free**. В терминале в папке проекта:

```powershell
npm ci
npx wrangler login
npm run cf:deploy
```

Подключать R2 в панели не нужно. Если предлагается выбор аккаунта, выберите нужный аккаунт; можно заранее задать `CLOUDFLARE_ACCOUNT_ID`.

Скрипт создаст локальный `.cloudflare-secrets.json` со случайными секретами сессий/бэкапов и сложным паролем первого администратора, опубликует Worker и создаст постоянные SQLite namespaces. Затем загрузит секреты, определит публичный адрес `*.workers.dev`, проверит страницу входа и, при наличии токена бота, настроит Telegram.

Адрес появится в терминале. Логин по умолчанию: **admin@team.local**. Пароль находится в поле **SEED_ADMIN_PASSWORD** файла `.cloudflare-secrets.json`. Этот файл исключён из Git; храните его локально для следующих деплоев. После первого входа пароль можно сменить в профиле — seed существующего пользователя не перезаписывает.

Повторное обновление: `git pull`, `npm ci`, `npm run cf:deploy`. Обновление кода не очищает базу или файлы.

## Лимиты хранения

В приложении установлены отдельные бюджеты, чтобы файлы не занимали пространство базы CRM:

| Данные | Ограничение по умолчанию |
| --- | --- |
| Изображения ленты | 256 МиБ суммарно; одно изображение до 8 МиБ |
| Архив резервных копий | 64 МиБ суммарно; до 20 последних копий |
| Одна JSON-копия / восстановление | До 20 МиБ |
| Файл Excel/CSV для импорта | До 5 МиБ |

Большие файлы хранятся двоичными фрагментами по 256 КиБ. Незавершённая загрузка не видна пользователям и очищается после перезапуска. Замена файла атомарная: при ошибке сохраняется предыдущая версия. Изображения выдаются только после входа в CRM.

При заполнении бюджета изображений сервер возвращает 507 с понятным сообщением, существующие файлы не удаляются. Для архива автоматически удаляются наиболее старые копии по общему объёму и количеству. Новая слишком большая копия отклоняется без удаления последней действующей копии.

При необходимости лимиты можно изменить в `vars` файла `wrangler.jsonc`: `FILES_MAX_BYTES`, `BACKUP_MAX_BYTES`, `BACKUP_MAX_COUNT`. Значения задаются в байтах/штуках. Код допускает до 512 МиБ изображений и 256 МиБ архива; увеличение не отменяет квоты Cloudflare. Квоты аккаунта также учитывают другие приложения.

## Telegram, напоминания и лиды

Без токена CRM работает с отключёнными Telegram-уведомлениями. Добавьте в `.cloudflare-secrets.json`:

- `TELEGRAM_BOT_TOKEN`: токен от BotFather;
- `TELEGRAM_BOT_USERNAME`: username без `@`.

Затем выполните `npm run cf:deploy`. Секрет webhook сгенерируется автоматически. Сохраняются привязка аккаунта через профиль, вход в Mini App, кнопки выполнения, уведомления о назначении/комментариях, напоминания и дайджест. Неудачные отправки остаются в постоянной очереди и повторяются по расписанию. Входящие webhook проверяются по секретному заголовку, повторные update_id отсекаются.

Для приёма лидов добавьте `OUTREACH_API_TOKEN` в тот же файл и повторите деплой. Endpoint остаётся `/api/outreach/events`.

Cron запускается каждую минуту: проверяет напоминания, обслуживает корзину и создаёт ежедневную резервную копию. Часовой пояс команды задаётся `TZ` в `wrangler.jsonc` (по умолчанию `Europe/Moscow`). Даты, `.ics` и напоминания используют его независимо от UTC среды Cloudflare и пояса браузера.

## Собственный домен

В панели: **Workers & Pages → pulsaura-crm → Settings → Domains & Routes → Add → Custom Domain**. После подключения домена замените `APP_URL` в `.cloudflare-secrets.json` на `https://ваш-домен` и выполните `npm run cf:deploy`: ссылки и webhook обновятся.

## Деплой из GitHub через панель Cloudflare

Создайте Worker из репозитория `TesHokay/notes`, ветка `main`, корень репозитория.

- Build command: `npm run cf:build`.
- Deploy command: `npx wrangler deploy`.
- R2 buckets создавать не нужно; оба хранилища описаны в `wrangler.jsonc`.

В **Worker Settings → Variables and Secrets** задайте секреты `SESSION_SECRET` (32+ случайных символа), `SEED_ADMIN_PASSWORD` (12+ символов), `BACKUP_ADMIN_TOKEN` (32+ случайных символа) и `APP_URL` с публичным HTTPS-адресом Worker. Если страница возвращает 503 из-за отсутствующих секретов, добавьте их и повторите deployment.

Для Telegram также задайте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` и `TELEGRAM_WEBHOOK_SECRET` (24+ символа). Webhook настраивается через скрипт `scripts/configure-telegram.mjs` с локальным файлом секретов или официальным методом Telegram `setWebhook`.

Не используйте генерацию локальных секретов как build command. Для CI-деплоя командой `npm run cf:deploy` передавайте постоянные `SESSION_SECRET`, `SEED_ADMIN_PASSWORD`, `BACKUP_ADMIN_TOKEN` через секреты окружения CI.

## Локальная версия Cloudflare

```powershell
npm ci
Copy-Item .dev.vars.example .dev.vars
npm run cf:dev
```

Адрес: http://localhost:8787. Локальный вход: `admin@team.local` / `local-admin-change-me`. Данные Wrangler находятся в `.wrangler/`, не связаны с опубликованной CRM и не загружаются при деплое.

Проверки:

```powershell
npm run check
npm test
npm run cf:check
npx playwright install chromium
npm run test:cloudflare
```

Интеграционная проверка использует изолированные SQLite namespaces в `tmp/`. Она запускает браузерные сценарии, проверяет файлы размером более 1 МиБ, сохранение после перезапуска, импорт, права, квоты, бэкапы, восстановление и Cron. Производственные данные не затрагиваются.

## Резервные копии и перенос базы

Ежедневно и перед удалением клиента/пространства создаётся JSON-копия в отдельном файловом Durable Object. При восстановлении базы CRM изображения и архив копий остаются в своём namespace. Для независимой копии скачивайте важные бэкапы на свой компьютер.

Для вошедшего владельца с заголовком `X-CRM-Backup-Token: <BACKUP_ADMIN_TOKEN>` доступны:

- `GET /admin/backups` — список копий;
- `POST /admin/backups` — создать копию;
- `GET /admin/backups/<имя>.json` — скачать;
- `GET /admin/backups/storage` — занятое место и лимиты файлов/архива;
- `POST /admin/backups/restore` — multipart-поля `backup` (JSON-файл), `password` (текущий пароль владельца), `confirm=RESTORE`.

Секрет хранится в `.cloudflare-secrets.json`. Обычной роли владельца команды недостаточно для скачивания всей базы: копия содержит также личные пространства. Перед восстановлением сохраняется ещё одна копия. Восстановление транзакционное, проверяет внешние ключи и требует повторного входа; текущие записи заменяются данными копии.

Для экспорта существующей SQLite-базы текущей версии: `npm run cf:export`. Получится `data/cloudflare-export.json`; исходная база читается без изменения. Экспорт переносится через endpoint восстановления и не содержит изображения.

Новый деплой начинает с новой базы и первого администратора; локальная база автоматически в интернет не отправляется. При обновлении версии с прежней конфигурацией база `CrmDatabase` сохраняется: миграция `v2` добавляет только `CrmFiles`. Файлы из старого R2-хранилища автоматически не переносятся.

Логи: `npx wrangler tail`. Проверка пакета без публикации: `npm run cf:check`.

Официальные справочники: [SQLite Durable Objects](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/), [Workers Free и Paid для Durable Objects](https://developers.cloudflare.com/durable-objects/platform/pricing/), [лимиты хранения](https://developers.cloudflare.com/durable-objects/platform/limits/).
