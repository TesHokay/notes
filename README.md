# PulsAura — внутренняя система управления работой

**Деплой в Cloudflare готов:** [инструкция и команды](CLOUDFLARE.md).
База, файлы и бэкапы — постоянные SQLite-backed Durable Objects, Telegram — webhook.
R2 и подключение платёжного метода для этой конфигурации не нужны; используйте Workers Free.


Не просто CRM, а мульти-пространственная система для всего агентства:
Sales / Production / SEO / Strategy и т.д. как отдельные **пространства (Spaces)**
со своим составом участников и видимостью, внутри — проекты (с опциональной
привязкой к клиенту), доски с колонками, задачи с несколькими исполнителями,
подзадачи со своим исполнителем, единый персональный дашборд по всем
пространствам сразу, лёгкий командный фид (каналы/посты/реакции) и
уведомления в Telegram.

Стек: Node.js + Express + EJS + встроенный `node:sqlite` (без внешних БД и без
нативных зависимостей — `npm install` ничего не компилирует).

## Модель доступа

- **Владелец (`is_owner`)** — видит и может всё, включая приватные пространства
  типа Strategy. Обычно это вы и второй фаундер.
- **Пространство (Space)** видно только тем, кто в нём состоит (`space_members`).
  Не состоишь — пространство просто не существует в меню, как Strategy для
  остальных.
- Роль внутри пространства (своя для каждого space, не глобальная):
  - **manager** — видит все задачи во всех проектах пространства;
  - **member** — видит задачи по правилу проекта (см. ниже);
  - **guest** — видит только те задачи/подзадачи, где назначен лично,
    независимо от правила проекта.
- У каждого **проекта** есть режим `task_visibility`:
  - `all_members` — все участники пространства видят все задачи проекта;
  - `assignees_and_managers` — участник видит только свои задачи, менеджеры и
    владелец — всё.
- Задача видна человеку, если он владелец / менеджер пространства / назначен
  на задачу или на любую из её подзадач / проект открыт для всех. Это верно,
  даже если человек не состоит в пространстве вообще — так дизайнер может
  получить одну задачу из Production, не имея доступа к остальной доске.
- Личный дашборд (`/`) собирает по пользователю задачи из **всех** пространств
  и проектов через таблицу `task_assignees`, независимо от членства в
  пространстве — ровно то самое «мне похуй, в каком пространстве лежит
  задача» из ТЗ.
- Дашборд владельца дополнительно показывает загрузку команды (просрочено /
  на сегодня / без исполнителя, и список людей с числом открытых задач —
  клик показывает загрузку конкретного человека).

## Запуск локально

```bash
npm install
cp .env.example .env      # поправьте значения при необходимости
npm run seed               # создаст владельца, 4 пространства и инвайт-код
npm start
```

Откройте http://localhost:3000, войдите под `admin@team.local` / `admin123`
(или тем, что указали в `.env`), смените пароль. Дальше — «Команда» → создать
остальных сотрудников → зайти в нужное пространство → «Добавить участника».

## Telegram-уведомления

1. Создайте бота через [@BotFather](https://t.me/BotFather) → `/newbot`, получите токен.
2. В `.env` впишите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME` (без `@`).
3. Задайте `APP_URL` — реальный адрес сайта.
4. Перезапустите сервис. Каждый сотрудник заходит в «Профиль» → «Подключить
   Telegram» → жмёт кнопку → бот привязывает аккаунт.

Что уходит в Telegram:
- назначение задачи (с кнопками «✅ Готово» / «Открыть» прямо в сообщении);
- новый комментарий к задаче, где вы исполнитель или автор;
- дедлайн сегодня / просрочка;
- утренний дайджест владельцам (задачи на сегодня, просрочки, задачи без исполнителя).

Без токена сервис работает как обычно, просто без уведомлений.

## Деплой на Beget (виртуальный хостинг, тариф уже есть)

Beget умеет запускать Node.js-приложения как управляемый процесс (не через
голый SSH-демон, который шаредхостинг убьёт):

1. Залейте файлы проекта в директорию сайта (файловый менеджер, FTP или
   `git clone` по SSH — SSH-доступ у вас включён).
2. В панели → «Сайты» → домен/поддомен → тип приложения **Node.js**, точка
   входа `server.js`, версия Node 22+.
3. В переменных окружения приложения задайте те же ключи, что в `.env.example`.
4. Beget сам поставит зависимости и будет держать процесс живым — важно и для
   сессий, и для long polling Telegram-бота.
5. Разово выполните `npm run seed` через «Терминал» в панели.

## Деплой через Docker (если решите переехать на VPS)

```bash
cp .env.example .env
docker compose up -d --build
```

Данные (SQLite-файл, загруженные картинки фида) хранятся в `./data` и
`./public/uploads` на хосте — переживают пересборку контейнера.

## Нужен ли мощный сервер?

Нет. Один лёгкий Node-процесс + файл SQLite, без отдельной СУБД. Хватит
самого дешёвого тарифа (1 vCPU, 512 МБ–1 ГБ RAM) — уже имеющегося у вас
тарифа Beget «Blog».

## Что упрощено относительно исходного ТЗ (осознанно, для скорости)

- Нет отдельной сущности `organizations` — компания одна, лишняя вложенность не нужна.
- Нет отдельного флага public/private у пространства — видимость и так
  полностью определяется членством, эффект тот же, сущностей меньше.
- Роли не глобальные, а per-space (гибче: можно быть manager в Production и
  member в Sales одновременно).
- У подзадачи один исполнитель, а не несколько — так и во всех примерах в ТЗ.
- В фиде один файл на пост (картинка), без полноценной системы вложений.
- Нет ещё «Все задачи» и «Календаря» в нижнем меню — по ним не было
  конкретики, дашборд уже закрывает 90% этой потребности.

## Проверки

```bash
npm run check      # синтаксис всех JS + компиляция всех EJS-шаблонов
npm test           # unit-тесты сервисного слоя (перемещение, порядок, выполнение)
# e2e-тесты A–I в браузере (нужен Playwright):
npm i -D playwright && npx playwright install chromium
node db/seed.js && node tests/e2e/fixtures.js && npm start   # чистая БД + тестовые данные
BASE=http://localhost:3000 npm run test:e2e
```

## Структура

- `db/` — схема SQLite и сид (владелец, пространства, каналы, инвайт-код)
- `lib/permissions.js` — вся логика видимости пространств/задач в одном месте
- `lib/telegram.js` — уведомления, привязка аккаунта, дневной дайджест
- `lib/task-service.js` — бизнес-логика задач: moveTask, выполнение, журнал активности
- `lib/dates.js` — даты в часовом поясе команды (TZ, по умолчанию Europe/Moscow)
- `views/partials/task-card.ejs`, `board-column.ejs`, `task/*` — карточка, колонка, drawer
- `public/js/board-dnd.js` — drag & drop, `board.js` — доска, `task.js` — drawer, `home.js` — Главная
- `routes/` — auth, dashboard, spaces, clients, projects, sections, tasks,
  feed, users, profile
- `views/` — EJS-шаблоны, `public/` — CSS и клиентский JS (drag-and-drop
  доски, инлайн-сохранение задачи, реакции в фиде)
